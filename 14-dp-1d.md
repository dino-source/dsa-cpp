# LeetCode Pattern: Dynamic Programming (1D)

## Overview

The Dynamic Programming (1D) pattern is used to solve problems where the
solution can be built from previously calculated smaller solutions.

The main idea is to define a state that represents the best answer up to a
certain position and reuse already computed results.

Instead of solving the same subproblem repeatedly:

```text
Brute force:
Recalculate the same states many times.

Dynamic programming:
Store previous results and reuse them.
```

1D Dynamic Programming is commonly used for:

- sequences;
- arrays;
- strings;
- optimization problems;
- counting possible solutions.

The most common steps are:

1. Define the state.
2. Find the transition.
3. Initialize base cases.
4. Compute the answer iteratively.

In C++, this pattern commonly uses:

- `std::vector`;
- arrays;
- variables for optimized space.

The key skill is recognizing when the current answer depends on previous
states.

## Pattern Recognition Checklist

Ask yourself:

- Does the problem have overlapping subproblems?
- Can the answer be built from previous answers?
- Am I making repeated choices over a sequence?
- Do I need the maximum, minimum, or number of possible solutions?
- Can I define an answer for each position?

If yes, 1D Dynamic Programming is likely a strong candidate.

## Common Dynamic Programming Variations

### Linear State DP

Each position depends on previous positions.

Example:

```text
dp[i] = best answer using elements up to index i
```

Typical examples:

- Climbing Stairs
- House Robber

---

### Decision DP

At each position, choose between multiple options.

Example:

```text
Take current element:

answer = previous + current value

Skip current element:

answer = previous best
```

Typical examples:

- House Robber
- Maximum Product Subarray

---

### Counting DP

Count the number of valid ways to reach a state.

Example:

```text
dp[i] = number of ways to reach position i
```

Typical examples:

- Climbing Stairs
- Decode Ways
- Word Break

---

## Space Optimization

Many 1D DP problems can reduce memory usage.

Instead of storing the entire array:

```text
dp[0]
dp[1]
dp[2]
dp[3]
...
```

Keep only the states needed for the next calculation:

```text
previous
current
```

This can reduce:

- Space complexity: `O(n)`

to:

- Space complexity: `O(1)`

---

## Complexity

Most 1D Dynamic Programming solutions have:

- Time complexity: `O(n)`
- Space complexity: `O(n)`

The space can often be optimized to:

- Space complexity: `O(1)`

when only previous states are required.
